# IA Pessoal 1.5

## Escopo e preservação

A auditoria confirmou SQLite local, consentimento de contexto manual, conversas separadas, recuperação por ID, cota D1 e revisões determinísticas na 1.4. A branch 1.5 conserva essas bases. A migração acrescenta uma autorização automática por memória e versão, uma coluna de proveniência na fila e tabelas aditivas de análise/push. Nenhuma tabela ou segredo anterior é removido. Os recibos antigos continuam no gateway em que foram cifrados.

## Funcionalidades

| Área | Implementação e limite |
| --- | --- |
| Pesquisa | Wikipédia em português, Crossref e Europe PMC por HTTPS, hosts fixos, metadados publicados, DOI e links verificáveis. Uma fonte ausente é sinalizada. Envio de até quatro referências na pergunta após o filtro de tamanho. Não é um buscador de toda a web ou serviço de preços em tempo real. A comparação usa as referências anexadas e declara lacunas. |
| Modos de busca | Confirmação por padrão, automática mediante consentimento persistente, e desativada. O reconhecimento de tema atual é heurístico. Envia apenas o tema, sem memórias ou perfil. O filtro de dados pessoais é conservador, mas não reconhece todo tipo de dado sensível. |
| Memória | Permissão separada por registro e versão. O app sugere automaticamente no máximo uma memória elegível; a fila verifica a autorização no instante do envio. Editar, tornar privado, excluir ou revogar invalida a autorização. |
| Cálculo e risco | A pergunta “Quanto é 18% de R$ 3.450?” usa aritmética exata e não chama o modelo. O fluxo de cálculo por ferramenta da 1.4 continua. Questões financeiras reconhecidas passam ao 120B com instruções para explicitar premissas, custos, margem, prazo e risco. |
| Revisões | Opt-in adicional por projeto. Fila/Cron selecionam eventos posteriores à autorização. O modelo recebe só título, descrição, objetivo e pendência. O processo registra resultado cifrado por sete dias, estado e ação sugerida. Contexto inalterado não gera nova inferência depois de uma revisão bem-sucedida. O app abre a análise como rascunho, aguardando confirmação de envio. |
| Cotas | No máximo duas inferências automáticas e 900 Neurons estimados por dia UTC, além da barreira compartilhada de 100 tentativas ou 5.000 Neurons. Limite de 12 pesquisas ao dia. Sem rota paga, sem retentativa automática de inferência incerta e sem cobrança ativada. |
| Push | Cadastro autenticado de um dispositivo por proprietário, janela horária em São Paulo, prévia genérica e uma tentativa por dia local. O registro separa aceitação pelo Expo de falha ou estado desconhecido; aceitação não comprova entrega. O toque abre Projetos. Push está desabilitado no Expo Go. |
| Backup | AES-256-GCM com chave separada. Formatos 1.4 e 1.5 na restauração. A 1.5 exporta conversas, memórias, preferências permitidas, projetos e histórico de iniciativas cadastrais quando conectado. Não contém credenciais, tokens, arquivo de foto, permissões de automação ou análises de retenção temporária. A restauração exige confirmação, ignora conflitos e não reenvia mensagens. Projetos entram pausados e iniciativas importadas como lidas. A gravação é transacional em cada base, não entre D1 e SQLite. Se a restauração local falhar após o D1, uma nova tentativa com o mesmo arquivo ignora duplicatas. |
| Segurança | O serviço continua de um proprietário. Uma conta compartilhada não oferece isolamento multiusuário. |

## Publicação e rollback

A [prévia 1.5](https://iapessoal-preview-v15.km-prospect-ai-app.workers.dev/) usa o mesmo escopo Expo das anteriores. O código prevê gateway e fila independentes no Workers Free, com o D1 já existente de autenticação e cota. A implantação de servidor precisa estar confirmada separadamente. Só use **Ajustes → Conectar ao gateway 1.5** quando ele estiver publicado. Para voltar à [1.4](https://iapessoal-preview-v14.km-prospect-ai-app.workers.dev/), selecione seu endpoint original nos Ajustes.

O push em iPhone/Android exige: vincular um projeto EAS para obter seu ID, configurar APNs e FCM conforme a plataforma e gerar a build de desenvolvimento com o perfil `development` em `mobile/eas.json`. Registre o aparelho na build, ative push nos Ajustes e valide recepção e toque com o app fechado. Se o projeto Expo exigir segurança aprimorada, defina `EXPO_PUSH_ACCESS_TOKEN` no Worker. Esses passos dependem de acesso do proprietário, não foram executados com conta ou aparelho físicos e não devem ser contratados sem aprovação.

## Testes locais

```sh
node --test server/cloudflare/*.test.mjs
(cd server && python -m unittest -q)
cd mobile
npm ci
npm run check
npm test
npx expo export --platform all --no-bytecode
```

Os testes controlados exercitam permissão, concorrência, cota, revisão cifrada, cálculo, seleção financeira, recuperação, validação do backup e restauração pausada. Os testes de serviço externo e de aparelho são reportados separadamente. No iPhone, teste primeiro um tema público, um projeto fictício autorizado e um backup sem dados importantes.
