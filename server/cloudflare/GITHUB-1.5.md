# Análises agendadas e monitoramento GitHub da IA Pessoal 1.5

A análise agendada exige acompanhamento global ativo, projeto ativo e autorização de inferência para o objetivo antes da revisão. A fila e o Cron chamam a mesma rotina de revisão. O gateway reserva a cota em D1, roda Workers AI e cifra os resultados com AES-GCM. O aplicativo recupera o resultado ao abrir e ao retornar ao primeiro plano. O cartão mostra a análise concluída quando o resultado ainda está disponível. A ação **Discutir análise** inclui o resultado existente no contexto de uma eventual mensagem. A retenção dos resultados agendados continua em sete dias.

## Vincular o GitHub

A implantação pessoal suporta uma GitHub App privada e uma instalação, vinculadas à credencial de proprietário já existente do gateway. Um administrador do GitHub precisa instalar a GitHub App. Não é preciso criar ou enviar um token pessoal.

1. Em **GitHub → Settings → Developer settings → GitHub Apps**, crie uma GitHub App privada, instalável apenas na própria conta. Use a URL inicial do gateway e configure o webhook em `https://iapessoal-gateway-v15.km-prospect-ai-app.workers.dev/github/webhook`, com um segredo aleatório forte. Não é necessário configurar OAuth de usuário.
2. Use somente **Read-only** em **Metadata**, **Contents**, **Issues** e **Pull requests**. Assine **Push**, **Pull request**, **Issues** e **Repository** e mantenha as notificações de mudanças na instalação. O proprietário confirma **All repositories** na tela oficial do GitHub para incluir repositórios atuais e futuros. **Only select repositories** também funciona com uma lista autorizada menor. Para uma organização, o administrador pode precisar aprovar a instalação.
3. Em **Workers & Pages → iapessoal-gateway-v15 → Settings → Variables and Secrets**, configure `GITHUB_APP_ID` com o ID numérico e `GITHUB_INSTALLATION_ID` com o ID numérico que aparece no endereço da instalação. Opcionalmente, defina `GITHUB_APP_SLUG` com o slug público da GitHub App para abrir sua instalação oficial pelo botão no iPhone. Cadastre `GITHUB_WEBHOOK_SECRET` e `GITHUB_PRIVATE_KEY` como **Secret**. O gateway aceita chaves RSA em PEM PKCS#1 (`BEGIN RSA PRIVATE KEY`) e PKCS#8 (`BEGIN PRIVATE KEY`). Mantenha a chave fora do código, da conversa e de logs.
4. O Cron sincroniza as páginas da instalação automaticamente depois que o gateway recebe os identificadores e segredos. Abra **Projetos → Repositórios GitHub** para conferir a última sincronização, acompanhar resultados, pausar tudo ou pausar um repositório. **Sincronizar repositórios** antecipa a próxima consulta. A instalação concede acesso aos arquivos e metadados autorizados. O monitor envia trechos selecionados ao Workers AI para análise.
5. **Pausar todos** interrompe as análises e mantém a lista sincronizada. **Desconectar conta** interrompe as consultas e preserva o histórico. Para revogar também a concessão do GitHub, suspenda ou desinstale a GitHub App no GitHub. Uma substituição por outro ID de instalação exige intervenção administrativa para preservar o isolamento da instalação anterior.

## Escopo, custo e evidência

- Webhooks com HMAC SHA-256 sinalizam mudanças da branch padrão, issues e pull requests. O gateway agrupa eventos por cerca de cinco minutos. O Cron existente recolhe um repositório por execução e verifica periodicamente os ativos, mesmo sem webhooks. O inventário percorre uma página de 50 repositórios por execução e faz uma reconciliação completa a cada seis horas. Repositórios arquivados ou que saíram da instalação ficam identificados e deixam de ser analisados. Uma resposta parcial ou falha de rede não confirma remoções.
- Uma execução compara o SHA anterior com o SHA atual quando possível e inspeciona até quatro arquivos elegíveis fixados no commit, além de até cinco títulos de issues ou PRs abertas. A revisão é amostral. Arquivos de credenciais reconhecíveis são excluídos, assim como alguns formatos comuns de segredo encontrados no conteúdo. Restrinja a instalação a repositórios cujo código pode ser processado pelo Workers AI.
- O gateway verifica o caminho e a linha indicados e reconstrói o trecho diretamente do arquivo lido. O vínculo com o commit e a linha permite verificar a referência. Impacto, prioridade e confiança são avaliações do modelo. Marque manualmente uma descoberta como resolvida após verificar a correção. A deduplicação usa arquivo, trecho e descrição, portanto alterações de redação podem produzir uma nova entrada.
- O monitor usa Llama 3.1 8B, até duas chamadas e até 800 Neurons reservados por dia. O teto global para o monitor está abaixo da cota de chat. A execução para ou adia quando falta cota. A API usa tokens de instalação de duração limitada e escopo reduzido ao repositório em análise. Não há escrita em repositórios nem execução de código.
- A verificação de código-fonte requer uma GitHub App instalada e um repositório autorizado. O fluxo de notificação reutiliza o limite diário e a janela configurada, sem conteúdo privado na notificação. A entrega push ainda exige uma build nativa configurada e teste em aparelho.
